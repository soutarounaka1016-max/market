# 社会ニーズ発見レーダー：事業機会の仮説評価と類似課題の発見

## 今回の目的

現在のアプリは、GitHub IssuesとHacker Newsから課題候補を取得し、候補を検索・整理・保存できます。

次の段階として、単なる「課題らしさ」だけでなく、保存する前に事業機会として追加調査する価値がありそうかを、根拠付きで比較できるようにしてください。

ただし、単一の投稿だけから市場規模、収益性、成功確率を断定してはいけません。今回実装するものは、あくまで追加調査の優先順位を決めるための「事業機会仮説スコア」です。画面と文書でこの制限を明記してください。

計画だけ、一部実装だけで停止せず、以下のフェーズを順番に実行してください。各フェーズで、現状確認、実装、テスト、不具合修正、再テスト、文書更新を行ってください。重大な停止理由がない限り、完成条件を満たすまで続けてください。

# フェーズ1：事業機会仮説スコア

各候補に、0〜100点の「事業機会仮説スコア」を追加してください。

これは現在の「課題らしさ目安」とは別の指標です。

## 評価軸

次の5軸を、それぞれ0〜20点で評価してください。

1. **困りごとの強さ**
   - 作業不能、損失、頻繁な失敗、強い不満などの表現
   - 再現手順や具体的影響がある

2. **広がりの兆候**
   - 複数コメント、反応、ポイント、同意表現
   - 「自分も困っている」「多くの人が使う」などの記述
   - ただしコメント数やポイントだけで高得点にしない

3. **継続・反復性**
   - 毎日、毎週、毎回、繰り返し、長年などの表現
   - 一度限りの障害やニュースより、繰り返される課題を優先

4. **支払者・利用者の明確さ**
   - 会社、チーム、学校、開発者、管理者、保護者など、誰が困り誰が支払う可能性があるか推測できる
   - 候補本文だけでは不明な場合は低得点にする

5. **解決余地**
   - 現在の回避策が面倒、不完全、手作業、代替が弱い
   - 単なる既知バグ修正や既存製品の宣伝だけなら低くする

## 必須条件

- 合計点だけでなく各軸の点数を表示する
- 各軸に短い根拠を表示する
- 根拠は取得データから確認できる内容に限定する
- 不明な項目は「情報不足」と表示する
- 事実と推測を区別する
- 市場規模、売上、成功率を架空に算出しない
- 1つのキーワードだけで極端な高得点にしない
- 点数は純粋関数で計算し、重みやキーワード群を定数化する
- GitHub IssuesとHacker Newsの違いを考慮する
- 日本語と英語の代表的な表現を扱う

表示名は必ず「事業機会仮説スコア」にしてください。「市場価値」「成功確率」など、断定的な名前にしないでください。

# フェーズ3：類似課題のグループ化

取得済み候補の中から、似た課題を簡易的にまとめて表示してください。

外部AI API、有料サービス、APIキーは使わないでください。現在の静的GitHub Pages構成で動く範囲にしてください。

## 最低要件

- タイトルと本文を正規化する
- HTML除去後のテキストを利用する
- ストップワードを除く
- 英単語は小文字化する
- 単語または短いフレーズの重なりを利用する
- 類似度のしきい値を定数化する
- 2件以上まとまったものだけグループとして表示する
- 同じ候補が複数グループへ重複しすぎないようにする
- 件数が1件しかない候補は通常一覧に残す

## グループ表示

各グループに次を表示してください。

- 仮のグループ名
- 含まれる候補数
- 情報源の内訳
- 平均事業機会仮説スコア
- 共通している主な語
- 含まれる候補一覧

グループ名を完全に自動生成できない場合は、共通語を利用した仮名で構いません。ただし「AIが意味を理解して分類した」と誤解させない表現にしてください。

表示は通常の候補一覧と切り替えられるようにしてください。

# フェーズ4：手動で仮説を補う機能

自動評価だけでは支払者や市場の情報が不足するため、保存済み課題に次の手動項目を追加してください。

- 想定利用者
- 想定支払者
- 現在の代替手段
- 困る頻度：不明 / 単発 / 月数回 / 週数回 / 毎日
- 困りごとの大きさ：不明 / 小 / 中 / 大
- 追加調査メモ

古いデータでは空欄または「不明」として扱ってください。

手動項目を入力した後は、事業機会仮説スコアを自動で都合よく上げないでください。自動評価と人間が入力した仮説を別表示にしてください。

保存、編集、JSON書き出し・読み込みでこれらの項目を保持してください。

- タイトル

ユーザーが調査済みとしてチェックできるようにし、その状態をlocalStorageとJSONへ保存してください。
