# 社会ニーズ発見レーダー

社会に存在する不満、面倒な作業、企業の非効率、新しいニーズを記録し、将来の事業候補として整理するためのブラウザアプリです。学校支給iPadのSafariやGitHub Pagesで使いやすいよう、追加ビルドなしの静的ファイルで動きます。

## 現在できること

* 課題の手動登録、編集、削除、localStorage保存、再読み込み後の復元
* GitHub IssuesとHacker Newsからの候補取得
* 取得候補の検索、絞り込み、並べ替え、件数確認
* 候補ごとの「課題らしさ目安」と加点・減点理由の表示
* 候補の個別保存と重複防止
* 保存済み課題の検討状態、自分用メモ、手動タグ管理
* 保存済み課題の検索、絞り込み、並べ替え
* 保存済み課題のJSON書き出しとJSONからの追加・統合

## 使い方

### 手動で課題を登録する

1. `index.html` をブラウザで開きます。
2. 左側のフォームにタイトル、内容、困っている人、支払者候補、情報源を入力します。
3. 必要に応じて検討状態、自分用メモ、手動タグを入力します。
4. 「登録する」を押します。
5. 保存済み課題一覧の「編集」「削除」で変更できます。

### 外部情報から候補を取得する

1. 「外部から課題候補を取得」で情報源を選びます。
2. GitHub Issuesの場合は `owner/repo` またはGitHubリポジトリURLを入力します。
3. Hacker Newsの場合は検索語を入力します。空欄なら既定の検索語を使います。
4. Hacker Newsでは取得件数、取得順、投稿種別を選べます。
5. 検索例ボタンを押すと入力欄に例が入ります。押しただけでは通信しません。
6. 「候補を取得」を押します。

## 候補の選別

保存前候補では、次の条件を組み合わせられます。

* キーワード検索（タイトル、本文、投稿者、タグ、情報源名など）
* 情報源（すべて / GitHub Issues / Hacker News）
* 保存状態（すべて / 未保存のみ / 保存済みのみ）
* 最低コメント数
* 最低スコアまたはポイント
* 並べ替え（課題らしさ、新しい順、コメント数、スコア、取得順）

取得総数、絞り込み後件数、未保存件数、保存済み件数も表示されます。一括保存はありません。内容を確認して、必要な候補だけ「課題として保存」を押してください。

## 課題らしさ目安について

課題らしさ目安は0〜100点で表示されます。これはAI評価、事業性、収益性、成功確率ではありません。AI APIは使わず、次のような説明可能なルールだけで計算します。

* 加点例：具体的な本文、困りごとを示す語、bug/problem/help wanted/enhancement系ラベル、複数コメント、Ask HN投稿
* 減点例：本文なし、短い本文、依存関係更新、リリース作業、求人、告知、Show HNの製品紹介寄り投稿

候補カードには主な加点理由と減点理由が表示されます。

## 保存済み課題の整理

保存済み課題には、次を追加できます。

* 検討状態：未確認 / 有望 / 保留 / 除外
* 自分用メモ：日本語での要約、気になった理由、追加調査、想定利用者、解決案の仮説など
* 手動タグ：カンマ区切り。重複、空タグ、前後空白は自動で整理されます。

保存済み課題は、状態、情報源、タグ、キーワード、最低課題らしさで絞り込み、更新日、登録日、課題らしさ、状態、タイトルで並べ替えられます。

## JSONバックアップと復元

「JSONを書き出す」を押すと、保存済み課題だけを次の形式で書き出します。一時的な取得候補は含みません。

```json
{
  "schemaVersion": 1,
  "exportedAt": "ISO日時",
  "appName": "社会ニーズ発見レーダー",
  "needs": []
}
```

JSONを読み込むときは、追加前に対象件数、新規追加件数、重複件数、不正件数を表示します。確認後に追加・統合できます。

重複判定には、ID、`sourceType` と `externalId`、`sourceUrl`、タイトルと作成日時の完全一致を使います。不正JSON、形式不正、1MBを超えるファイル、読み込める課題がない場合は日本語で警告します。

## 使用する外部API

GitHub REST APIのIssue一覧取得APIとHacker News Search API（Algolia）を使用します。

```text
https://api.github.com/repos/{owner}/{repo}/issues
https://hn.algolia.com/api/v1/search_by_date
https://hn.algolia.com/api/v1/search
```

認証トークン、APIキー、パスワードなどの秘密情報は不要です。GitHubの未認証レート制限を受ける可能性があります。

## GitHub Pagesで公開する場合

1. GitHubのリポジトリ設定を開きます。
2. Pagesの公開元をこのブランチのルートディレクトリにします。
3. 公開されたURLをSafariで開きます。

## iPadで確認すること

* 520px以下またはiPad幅で横スクロールが出ないか。
* ボタン、セレクト、入力欄が押しやすいか。
* 候補を20件以上表示しても操作しやすいか。
* 長いURLや英単語でカードが崩れないか。
* 保存前候補と保存済み課題が見分けやすいか。
* JSON書き出し・読み込みがSafariで実行できるか。

## 注意

* データはサーバーではなく、利用中のブラウザ内のlocalStorageに保存されます。
* 別端末や別ブラウザには自動同期されません。
* ブラウザのサイトデータを削除すると、保存した課題も消える可能性があります。
* 課題らしさ目安は仮説整理の補助であり、実在性や事業成功を保証しません。
